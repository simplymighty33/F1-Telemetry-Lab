# F1 Telemetry Lab 1.0.3a — 练习复盘开发版

界面版本1.0.3a，Python版本号1.0.3a0，Windows数值版本1.0.3.0。此为本地开发/验收版，不自动替换GitHub正式发行的1.0.2。

## 四项工作

1. 真实长测准备：附操作与验收清单，新增流式只读档案审计，校验CRC、逐包Header重打包、录制索引字段及已有基础缓存Header；默认摘要排除玩家身份、UID值、IP和私人路径。新GUI录制每秒附驻留/私有内存首末峰值到资源摘要，不增加界面数字卡片。实际游戏长测仍待用户运行，工具不会预先勾选“稳定”。
2. 练习段汇总：已提交数据库单快照，圈速/赛段逐圈表、最快/中位/极差/总体标准差，独立驾驶段/胎组分组。出入站/车库、无效、源质量不合格、待分析和玩家变化圈列明原因，不计入正常统计。最多最近120圈，明确显示未列圈数；未知胎组不等同于同一套胎。
3. 比较条件：核验同帧同玩家的Car Status、Telemetry来源，显示燃油起终采样、四轮平均内温中位值、ERS储能中位/模式集合与有效来源样本数。缺少证据/缓存来源不按已核验值展示；燃油端点仅取起终点200米范围内可验证样本。5 kg燃油、10°C内温、0.5 MJ储能差仅为提示门槛，不是有效性界限/修正模型。天气、设置、辅助、交通仍未完整校验。
4. 多圈重复性：固定100米区间，仅在基准与候选起终点及区间内部全部可靠时计算净时间差。使用所选基准及最多最近12个候选；不同已知配方/驾驶段不混入。至少2圈损失超过20ms、占已覆盖候选至少2/3、覆盖总候选至少2/3时显示“重复观察损失”。这是描述性门槛，非统计显著性、弯道编号或驾驶原因。双击有损失圈号的区间可定位主窗口当前双圈曲线；复盘自身为快照。

## 架构与兼容性

Raw及基础缓存格式不变。分析引擎8、派生schema5新增紧凑 `condition_frames` 标记。全量/缓存/增量共用同一个FrameWriter；Flashback来源通过有效样本连接，不读取被撤销分支的条件。

旧分析库直接打开仍只读。继续旧增量任务只添加派生表，不回放已处理Raw；过去未记录的同帧标记保持未知。旧检查点中的待拼接帧没有来源标记时也保守处理。需要完整历史证据时，用独立输出目录重建，不覆盖旧库。

汇总不生成新持久数据库，不增加第三方依赖。耗时任务在后台线程，查询限定单Session且逐圈处理；复盘最多120圈、候选12圈，控制内存和计算量。取消在圈/区间/Raw记录/哈希块边界检查，关闭等待线程正常退出。暂停采集时仍不能证明所有未发送/网络丢失的包；原始档案只证明实际收到的数据。

详细真实长测流程见 `ENDURANCE_1.0.3a.md`。自动化、历史Replay和打包程序验收结果保存在本地outputs，不作为新的真实长测结果宣传。

## 本地验证记录（2026-10-02）

- 自动化回归153项全部通过，包含筛选、条件来源、缺口排除、快照只读、窗口布局与取消退出。
- 既有624,609包录制：Raw、基础缓存、分批增量三条重建路径的17张派生表一致；12次Flashback，11个最终完整圈；55组双圈比较保持时间差守恒。原始文件SHA256未改变。
- 历史档案审计：CRC通过，Header重打包、录制索引与基础缓存Header不一致数均为0。历史录制缺少新版内存字段，不能用于证明新版的长期资源稳定性。
- 独立Windows EXE冒烟测试：模拟472包全部进入Raw、基础缓存与增量分析，解析错误0；自定义端口保存和重新加载、关闭窗口等待提示及正常退出通过。这是模拟接收测试，不替代真实游戏长测。
- 本机历史数据的练习复盘快照约1.5秒；仅作当前数据和机器的观察值，不保证其他录制或电脑的处理时间。
