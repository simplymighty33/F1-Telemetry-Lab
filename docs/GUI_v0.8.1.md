# v0.8.1：UDP 端口设置与统一安全退出

## 使用方式

主界面的状态区新增 **UDP 端口** 输入框和 **保存并重新监听** 按钮。输入与游戏 F1 23 设置一致的端口（整数 1–65535），点击按钮并确认，即可应用，无需重启程序。

切换时先停止旧监听、完整保存旧 Session、停止旧后台整理线程，再创建新 Session 并监听新端口。切换期间不接收数据，应在游戏暂停或进站后操作。窗口内旧逐圈记录清空，历史记录仍保存在旧 Session，旧分析窗口不被强制关闭。

端口保存到本次启动使用的 `config/settings.json`（若指定了 `--config` 则保存到指定文件），下次启动自动使用。仅修改 `udp_port`，保留其他配置，包括未知扩展字段。写入采用同目录临时文件、fsync 和原子替换。配置保存失败时原监听不停止。

这里编辑的是 **UDP 端口**，并不是远程目标地址。绑定地址仍由原配置 `bind_host` 决定，默认 `0.0.0.0` 监听本机全部 IPv4 网络接口；游戏端目的 IP 应指向运行本程序的电脑。CLI 的 `--port` 仍优先于保存值。若新端口被占用或无法绑定，窗口保留错误提示，可编辑端口重新尝试；不会自动切回不符合游戏设置的端口。

## 关闭保护

点击右上角 **X**、按 **Alt+F4**、或点击 **安全停止并关闭**，均使用同一安全关闭流程。

1. 显示“正在安全关闭”小窗口，拒绝重复关窗及新增任务；提示窗口不能手动提前关闭。
2. 停止 UDP 接收，等待 Raw 与包索引写入队列排空，写完元数据并关闭文件/数据库。
3. 等待后台基础整理停止，确认采集线程实际退出。基础整理仍遵循 v0.8.0 的有限追赶窗口，若大量积压则保存进度供后续恢复，并非强制要求全部缓存追上 Raw。
4. 等待本主窗口打开的所有分析窗口内正在进行的分析或 Raw 压缩任务完整结束，而不是强制中断；关闭日志后销毁主窗口及其所有子窗口、提示窗口。

单独关闭某个分析窗口（包括 `--analysis` 独立模式）也会先显示提示，等待该窗口的后台任务结束后再关闭。分析任务和压缩任务改为受跟踪的非 daemon 线程，工作函数只持有结果队列，不操作 Tk 控件。关闭期间任务的结果不再触发新的重试或错误对话框。

大文件分析、压缩和磁盘慢写可能需要较长等待；不设置一个会丢弃尚未完成工作的强制退出倒计时。此保护只适用于正常窗口关闭，不能保证任务管理器强制结束、系统断电、磁盘故障时所有工作完成；Raw 原有校验、事务和可恢复机制仍保留。

## 验证

- v0.8.0 的 56 项回归测试保留，新增端口/退出测试，合计 69 项。
- 输入非法、取消修改、配置写入失败：原采集不中断，原配置不被覆盖。
- 真实本机 UDP：旧端口收 100 包，切换后新端口收 250 包；两个不同 Session 的 Raw 和 foundation 均对应完整包数，元数据均 complete。
- 直接发送 WM_DELETE_WINDOW：执行同一安全流程；重复关闭、关闭提示窗口、切换途中关窗均不会跳过收尾或启动新的采集。
- 在原生确认/文件选择对话框仍打开时收到关闭请求，不会在对话框返回后启动新的监听或文件处理。
- 主窗口有多个分析/压缩任务时等待全部完成；单独分析窗口关闭也等待真实后台任务。
- 保留原显示缩放与最小窗口尺寸测试，按钮保持可见。

打包输出：`dist/F1TelemetryCollector-v0.8.1/`。部署到游戏电脑时复制整个文件夹，不要只复制 EXE。旧版本程序及采集数据不会被本次发布覆盖。
