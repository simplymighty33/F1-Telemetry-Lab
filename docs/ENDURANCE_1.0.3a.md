# 1.0.3a 真实游戏长测验收

开发测试与历史Raw回放已经用于回归检查，但不能代替这次真实长测。本清单保持未勾选，等实际测得数据后再验收。

## 准备

- 完整解压新程序，保留 `_internal`。不要覆盖旧版文件夹、录制和分析库；不要同时运行两版监听同一端口。
- 在有充足空间的磁盘测试。记下游戏、UDP协议/发送频率、Windows版本、开始结束时间和测试操作。不要在公开反馈中填写玩家身份/IP/私人路径。
- 长测建议先做30分钟冒烟检查，再做至少2小时或一场完整比赛；这是测试建议，并非已经证明的连续运行上限。

## 运行只读审计

在圈速分析窗口点击“练习复盘 / 审计”。已载入数据时，在复盘窗口点击“选择已停止的Session进行长测审计”；没有分析数据时可直接选择审计。必须先停止**所选录制**，不必移动大文件。

审计为后台流式扫描，关闭分析窗口会请求取消并等待线程退出。它不生成分析库，不重写Raw，不进行尾部恢复。窗口可将摘要另存为JSON。摘要去除身份、sessionUID值、源IP和私人路径，但仍含驾驶档案的统计，公开前请自行确认。

源码命令行也可运行：

```powershell
python -m collector.audit_session "D:\Recordings\session_example"
```

`archive_checks_passed`只表示该档案的已实施检查满足要求，不表示网络零丢包、所有游戏实测兼容或没有内存泄漏。`needs_review`表示存在不一致/缺少证据；例如旧录制没有基础缓存，或后台缓存未追上。中断/CRC损坏不会被默认为成功。

## 保留的证据

安全关闭后保留整个Session，包括Raw、metadata、录制索引、基础与分析库。至少保留自己的测试操作记录和去身份化审计摘要。完整档案只用于私下核查，不要默认上传GitHub。
