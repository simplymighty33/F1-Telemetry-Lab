# v0.9.1：逐圈轮胎信息

主界面新增轮胎配方、该圈结束前磨损，以及按轮胎使用段重置的圈号。分析选择框显示“软胎 第1圈（圈速）”，同时显示使用段次序和会话圈号，避免同配方、相同圈速的记录重名。

## 数据规则

- 使用 `visual_tyre_compound` 显示软、中、硬、半雨、全雨；不把实际 C0–C6 配方固定转换为软/中/硬。
- 首选 Session History 的 `tyre_stints` / `end_lap` 边界编号，255 表示当前使用段。同配方更换胎组仍从第1圈开始。
- 有本圈末实际状态时使用实际配方；真实练习赛样本出现历史 end_lap 边界与圈末配方相差一圈的情况，此时保留实际采样、调整分组，并在 `compound_source` 标注 `_over_history`。没有本圈采样时使用历史配方。
- 无历史边界时，从捕获到的配方、fitted_idx 或胎龄降低识别新的使用段；未捕获的历史不补造。
- 编号按使用段中的会话圈数计算，包含出站、回站和无效圈；不是旧胎的累计使用寿命。
- 磨损优先取该圈最后 Lap Data 帧之前最近4秒内 Car Damage 的四轮平均值，保留 RL/RR/FL/FR 原值和来源帧/会话时间；没有时可使用明确标记的 Tyre Sets 胎组磨损。
- 结束后冻结该圈数据；换胎或继续驾驶不能覆盖前圈磨损。乱序低频包仅可修正对应结束帧之前的快照。
- 历史圈速包可能滞后于终点线 Lap Data；未公布的最新完成圈快照不会因此被删除。
- Flashback 删除回退点之后的完成快照；重新完成后用新值替换。不同 Session/玩家不共用轮胎状态。
- 轮胎状态或磨损缺失、过旧、非有限数值、越界均不伪造为0。

## 兼容

新增派生表 `lap_tyres`，分析 schema v3 / engine v5；原基础缓存结构不变。默认结果保存在 `analysis_v0.9.1/`，旧结果目录保留。旧数据库只读打开时缺少轮胎表可继续正常对比；若需轮胎信息，从 Raw 或基础缓存重新生成分析。

## 验收

- 86 项自动测试通过，覆盖四种协议历史、同配方换胎重编号、圈末平均磨损、历史包延迟、历史边界偏差、Flashback、缺失/过期/异常数值、Tyre Sets 回退、旧数据库只读兼容，以及小窗口真实控件文字与滚动。
- 原长测 624,609 包、0 解析错误；Raw 和基础缓存生成的 `lap_tyres` 完全相同。原11张派生数据表逐行 SHA-256 与基准完全一致。
- 原样本11个可比较圈全部关联四轮磨损，前8圈中性胎、后3圈软胎；软胎段独立从第1圈开始。
- 实际冻结 EXE 472 包全数 Raw/基础保存，0 错误；换胎数据为软胎磨损8%、中性胎磨损12%，两段圈号均为1。主窗口及分析窗口安全退出码0，使用说明同级存在。
- 不新增第三方运行依赖。新增轮胎记录为每圈少量派生字段，后台保留有上限的近期观察，不保存第二份高频数据。

验收记录位于 `outputs/tyres_v0.9.1_long_final/tyre_verification.json` 和 `outputs/release_v0.9.1_final/release_verification.json`。
