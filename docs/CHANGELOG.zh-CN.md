# F1 Telemetry Lab：1.0 至 1.0.3 中文更新说明

更新日期：2026-10-02。当前正式版：**1.0.3**。本文说明从 1.0 发布到现在的主要新增能力、可靠性修整、升级注意事项及验证边界。

[下载当前 Windows 版本](https://github.com/simplymighty33/F1-Telemetry-Lab/releases/tag/v1.0.3) · [中文使用说明](F1TelemetryCollector-使用说明.txt) · [English release notes](RELEASE_1.0.3.en.md)

## 一、先看主要变化

从 1.0 的“可靠记录与基础单圈对比”，逐步发展到“区间时间差分析、练习复盘和更清晰的多会话数据管理”：

1. **看出时间差发生在哪里**：增加距离区间的获益/损失分析，可联动图表查看两圈的速度、制动、油门恢复及挡位差异。
2. **判断数据是否足以支持分析**：增加逐圈质量证据、采样缺口与时序检查；不能可靠归属的时间差单独显示，不强行解释为驾驶原因。
3. **一次复盘多圈练习**：按驾驶段、胎组汇总圈速与赛段，检查比较条件，观察同一区间是否在多圈反复出现时间损失。
4. **更容易找到、辨认数据**：统一赛道、比赛环节、总圈数、配方与磨损标签；新录制按游戏 Session 标识分档，文件夹名称可直接帮助查找。
5. **更稳、更顺畅地边跑边看**：强化 Raw 优先的资源保护，减少重复分析；耗时比较改为有界后台任务，并支持离线任务进度、安全取消与旧缓存独立重建。

## 三、1.0 已有的基础能力

以下内容在 1.0 已存在，不应误认为全部是 1.0.3 新增：

- 自动识别 F1 23/24/25 已支持的原生 UDP 格式，应用中可设置 UDP 端口；协议支持包括已实现的 F1 25 2026 Season Pack 格式。
- 最新圈优先的圈速与三个赛段记录、轮胎配方、圈末磨损及独立胎组圈数。
- 保存收到的完整 Raw 数据报，采用无损压缩与校验；不运行游戏也可离线 Replay。
- Flashback 保留原始证据，派生分析采用最终有效时间线。
- 距离对齐的速度、油门、制动与累计时间差曲线，制动/换挡事件及基础驾驶指标。
- 赛中后台增量分析，复用已完成结果；窗口关闭及安全退出均等待正常收尾。
- Windows 独立程序，完整解压后不需要另装 Python。

## 四、1.0.2：从整圈对比到可靠区间分析

### 4.1 时间获益/损失区间

- 将两圈比较进一步划分成距离区间，展示每段净时间获益或损失。
- 选择区间后联动图表缩放，查看该段的入口、最低、出口速度，以及制动、油门恢复和挡位证据。
- 以共同距离边界比较，不把不同位置的操作直接放在一起解释。
- 累计差的正值表示对比圈更慢、负值表示更快；区间金额取有效端点差，不把平滑曲线当作实际计时。
- 补充有真实支持的起终端点和缺口边缘；没有观测到的车手输入不外推，最低速度点不冒充几何弯心。

### 4.2 时间差与质量证据

- 官方整圈时间差、可靠区间合计、未归属差额分开显示。未归属量可按起点、内部缺口、终点等位置列出，但这些是算术贡献，不是已经证明的原因。
- 检查样本覆盖、必要字段、游戏计时单调性与采样节奏。缺口不能用连线、插值或事件提取伪装成连续有效遥测。
- 增加逐圈质量详情、不完整帧证据、Raw 逻辑偏移范围及暂停/Session/Flashback 上下文；质量行可打开详情。
- 旧库比较也从可用源样本重新核验，并在一个只读快照中取得相关数据，避免后台更新时混合不同时间线。
- 轮胎配方和磨损差异会提示；这些差异及操作差异都不能自动证明圈速损失的因果关系。

### 4.3 Raw 优先的采集保护

- Raw 写入队列达到 60% 压力时，后台派生工作在安全批次边界暂缓；降至 25% 以下恢复。
- 剩余空间不足 1 GiB 时暂缓派生工作并告警；不足 128 MiB 时安全停止接收，窗口仍保留供用户查看和退出。
- 分析积压达到至少 10,000 包时提示；合并不必要的界面刷新，但不丢弃 Raw 或权威圈历史。
- 写入失败与队列溢出明确报错，不以“仍在运行”的假象掩盖失败。资源摘要记录压力、空间与积压观察值，不冒称精确丢包统计。

## 五、1.0.3：练习复盘、上下文与 Session 分档

### 5.1 练习段汇总

- 增加驾驶段/胎组分组、逐圈与逐赛段表，以及最快、中位、极差和总体标准差。
- 出入站/车库、无效、质量不合格、尚待分析及玩家变化的圈列明原因，不混入正常统计；未知胎组不视作同一套胎。
- 复盘使用已提交数据库的单快照，最多展示最近 120 圈，并说明未列出的数量；它不是无限范围的实时自动评分。

### 5.2 比较条件与多圈重复观察

- 检查有来源证据的燃油、轮胎内温与 ERS 数据；区分可核验的同帧来源与仅有缓存/缺少来源的情况，不把未知写成可靠数值。
- 燃油起终采样仅在起终点附近 200 米范围内取得；5 kg 燃油、10°C 内温、0.5 MJ 储能差为提示门槛，不是圈速修正模型或有效性标准。
- 以固定 100 米区间，观察所选基准与最多最近 12 个候选圈的净时间差；已知不同配方/驾驶段不混用，区间起终及内部必须有可靠支持。
- “重复观察损失”要求至少两圈损失超过 20 ms，并满足覆盖与出现比例门槛。它是描述性观察，不是统计显著性、弯道编号或驾驶原因判断。
- 可从相关区间定位双圈曲线。天气、设置、驾驶辅助及交通条件仍未完整校验。

### 5.3 圈名与赛中分析入口

- 主界面、分析选择及练习复盘统一显示赛道、比赛环节与游戏会话总圈号。
- 示例：`澳大利亚 · 练习赛2 · 总第33圈｜软胎（磨损12.0%）｜1:22.000`。
- “总第33圈”是当前游戏会话的圈号，不跨练习、排位和比赛累计，也不因中途开始采集而改成第1圈。
- 标签使用配方与磨损，胎组身份和胎组圈数仍独立保留，不能把相同磨损当作同一胎组。磨损表示已经磨掉的比例，不是剩余寿命；缺失显示未知，真实 0% 仍显示 0.0%。
- 正常赛中从主界面打开单圈分析，自动连接当前档案，无需手动导入 Raw，也不因此触发全量 Replay。结果在后台提交后可见，不承诺过线即刻完成。
- 切换会话/玩家/协议时避免新标题配旧圈速；等待当前会话自己的结果。主动选择历史会话或数据库后不强制抢回当前采集。
- 已知练习和排位类型使用对应名称；Race/Race 2/Race 3 的冲刺/正赛细分缺少可靠依据时保留待确认，不靠圈数或顺序猜测。

### 5.4 按游戏 Session 自动分档

- 新录制按 `(packetFormat, sessionUID)` 路由，UDP 监听不中断。
- 目录示例：`session_20261002_153000_F1-23_澳大利亚_练习赛2_UID-000000000000004D`。
- 名称按首次接收时间和首次确认的赛道/环节生成；UID 完整保留，上下文后续变化记录在 metadata，不反复搬动活动分析目录。
- 每档保留 Raw、包索引、metadata 与自己的基础/分析缓存。旧 UID 的迟到包归回原档案，不能归属的输入另外保留，不猜测会话。
- 进站、换胎、完成一圈、Flashback、短暂静默不单独创建新档案；再次启动程序即使收到相同 UID，也创建新录制且不覆盖旧数据。
- 同一个 UID 后续可能改变上下文，不承诺每次环节变化必然产生新 UID。历史档案分析可能落后于迟到数据，停止后可增量补齐。
- 旧目录不批量拆分、改名或迁移。查找新历史数据时直接选名称对应的 Session 目录；迁移应在完全停止后复制整个目录。

## 六、1.0.3 正式版的审查整改

### 6.1 数据身份与故障隔离

- 验证合并帧中的玩家索引、协议和游戏帧号，不一致记录为 `identity_mismatch` 质量问题，不生成有效混合样本。
- 状态/损伤缓存按会话、协议、玩家隔离，不借用未来帧或未来时间的状态。
- 显示层异常不停止健康的 Raw 捕获，持续警告可见；真正的写盘失败和队列溢出仍明确停止。
- 状态查询不再等待慢 Raw 写盘锁；新会话初始化阶段不再显示上一会话的后台进度；后台收尾异常明确提示。

### 6.2 增量计算与界面响应

- 重复圈历史不再逐圈反复写入；仅更新受影响会话、圈、驾驶段与指标，必要的时间戳更新仍保留。
- 增加分析内容修订号，区分真实结果变化与仅包数/倒计时变化。
- 耗时双圈比较由单个有界后台任务处理，只保留一个最新待处理请求和最多四个缓存结果；旧结果不能覆盖新选择。
- 相同圈刷新保留图表缩放、可匹配的区间选择，以及正在浏览的圈表位置。
- 打开无效数据库前验证实际视图查询，失败时保留原选择与视图；最近数据库查找包含版本化结果目录。

### 6.3 缓存、任务及使用维护

- 新默认增量目录为 `analysis_v1.0.3/`。分析引擎、解码、模式、事件阈值及参数构成兼容签名，不兼容结果拒绝混写。
- 搬迁或不兼容旧缓存可确认后独立重建到新目录，包含新的基础缓存；旧库保留。仍在采集的档案不能走独立重建。
- 离线基础解析、分析和压缩提供阶段/数量与安全取消。分析保留已提交进度、回滚未提交事务；压缩取消不发布未核验副本，原件保留。
- 取消是协作式请求，不强制打断系统 I/O、刷盘或正在执行的单圈计算，因此有时仍需等待。
- 事件导出流式写盘；错误总数准确，详细样本最多 200 条，避免长任务积累无限错误明细。
- 拒绝 NaN/Infinity 和不合理的等待设置；整理当前中英文指南、保留历史说明，统一应用与 Windows 文件版本为 1.0.3。
- 默认诊断摘要排除玩家身份、IP 与私人路径。原始 Raw 本身仍包含完整接收信息，不能当作已脱敏文件直接公开上传。

## 七、验证结果与限制

- 1.0.3 本地交付源码和独立公开源码副本均通过 **192 项自动化回归测试**，覆盖身份混合、恢复、兼容、取消、视图保留、Session 路由及收尾故障等场景。
- 独立 EXE 对 **35 包合成档案**完成帮助、离线审计和压缩测试；压缩回放的逐包字节、接收时间、IP 与 CRC 与原件一致；下载 ZIP 的 CRC 与逐文件 SHA-256 校验通过。
- 历史 F1 23 的 **624,609 包、12 次 Flashback、11 个完成圈**曾用于多路径回放验证，但不是本次 1.0.3 新开展的游戏长测。早期版本的结果表数量和性能数据属于对应版本，不自动成为新引擎的完整验收结论。
- 同机五次“重复历史包更新”的合成测量：100 圈平均约 10.30→6.70 ms，500 圈约 22.65→8.61 ms；500 圈时 SQL 数量从 1,037→14，历史 INSERT 从 1,000→0。这不等于完整 Raw 重建速度或游戏 FPS。
- 无真实内容变化的一次界面回调测量约 277.757→0.681 ms，图表焦点保留；不能推广为所有界面操作的加速倍数。
- F1 24/25/2026 仍需对应真实游戏长测；冲刺周末、多环节切换和新分档功能也需实际数据验证。自动化布局不是人工目视验收。
- 没有刻意降低 Raw 采样、删除 AI 数组或增加第三方运行依赖。Raw 只能证明实际收到的数据，无法恢复网络中从未收到的包；帧缺口不等于准确 UDP 丢包率。
- 安全退出与校验不能保证断电、强杀或磁盘硬件故障时零损失。来源身份和 CRC 也不是密码学防篡改认证。
- 当前仍未提供赛道地图库、overlay、自动教练、驾驶因果诊断或 Setup 推荐。

## 八、下载与升级

1. 下载 Release 附件 **F1TelemetryLab-1.0.3-Windows-x64.zip**，完整解压，并保留 `_internal/` 与 EXE 同目录。GitHub 自动生成的 Source code ZIP 不是 Windows 安装包。
2. 保留旧程序、旧录制和配置；复制配置前停止两个版本，不要让多个程序争用同一 UDP 端口。
3. 游戏内仍需启用 UDP、正确设置目标地址和端口；自动识别协议不等于程序能代替用户修改游戏设置。
4. 旧 Raw v1/v2 继续可读，旧分析数据库仍可浏览。首次创建新算法结果或独立重建可能较慢，之后复用兼容缓存与已提交进度。
5. 复制 Session 前停止所有采集与处理，保留 metadata 和任何仍存在的 SQLite `-wal`/`-shm` 文件；不要只复制活动中的数据库主文件。
