F1 TELEMETRY LAB 1.0.2
程序使用说明
======================================================================

1.0.2 为统一公开发行版本，包含此前本地 1.1、1.2 的全部功能。
下文 1.1、1.2 为开发阶段名称，并非需另行安装的版本。

一、程序用途
----------------------------------------------------------------------
本程序用于接收、保存和分析 EA SPORTS F1 游戏通过 UDP 发出的遥测数据。

当前支持：
  · F1 23（2023 UDP 协议）
  · F1 24（2024 UDP 协议）
  · F1 25（2025 UDP 协议）
  · F1 25 2026 Season Pack（2026 UDP 协议）

程序会根据每个 UDP 数据包自动识别游戏和协议，不需要在程序中手动选择游戏。


二、使用前的重要提示
----------------------------------------------------------------------
1. 必须保留整个 F1TelemetryLab-1.0.2 文件夹。
   F1TelemetryLab.exe 旁边的“_internal”文件夹是程序运行所必需的，不能删除，
   也不要只把 EXE 单独复制到其他位置。

2. 建议将整个程序文件夹放在有写入权限、空间充足的位置，例如：
   D:\F1TelemetryLab-1.0.2

3. 不建议直接放在只读目录、系统目录或受严格保护的目录中。

4. 程序保存的是驾驶遥测数据。长时间测试或完整比赛前，请确认磁盘剩余空间充足。


三、游戏内 UDP 设置
----------------------------------------------------------------------
请在游戏的“设置 / Telemetry Settings（遥测设置）”中进行以下设置：

  UDP Telemetry：开启
  UDP Send Rate：建议 60 Hz
  UDP Port：默认 20777，必须与程序界面显示的端口相同
  UDP Format：使用对应游戏的默认原生格式即可

如果游戏和采集程序在同一台电脑：
  UDP IP Address 建议设为 127.0.0.1。

如果游戏和采集程序在两台电脑：
  UDP IP Address 应设为运行采集程序电脑的局域网 IPv4 地址，并允许程序通过
  Windows 防火墙的“专用网络”。建议使用有线局域网。

注意：程序可以自动识别 F1 23、F1 24、F1 25 和 2026 协议，但不能自动替用户
开启游戏内 UDP，也不能自动修正游戏内的目标 IP 和端口。


四、首次启动
----------------------------------------------------------------------
1. 双击 F1TelemetryLab.exe。
2. 如果 Windows 防火墙弹出提示，请允许程序访问专用网络。
3. 程序会在 EXE 同目录自动创建：

   config\settings.json     程序设置
   data\                    每次采集的数据
   logs\collector.log       运行日志

4. 启动后状态通常先显示“正在监听”，收到游戏数据后会变为正在接收状态。
5. “最近数据”时间持续变化，表示程序正在收到游戏发出的 UDP 数据。
6. 程序收到有效 Header 后，会自动显示游戏、模式、比赛阶段和赛道。


五、主界面说明
----------------------------------------------------------------------
1. 状态区域
   显示程序当前正在启动、监听、接收、保存、停止或发生错误。

2. UDP 端口
   默认端口为 20777。界面端口必须与游戏内 UDP Port 完全一致。

3. “保存并重新监听”
   输入 1 至 65535 的新端口后点击此按钮。程序会：
   · 安全结束当前 Session；
   · 保存新端口；
   · 创建新的 Session；
   · 在新端口重新监听。

   切换期间会短暂停止接收，因此建议在游戏暂停、进站或 Session 间隙操作，并同步
   修改游戏内端口。

4. 游戏、模式、比赛阶段、赛道
   这些信息来自游戏 UDP 数据。刚启动、菜单中或尚未收到对应数据包时可能暂时显示“—”。

5. 玩家逐圈记录
   显示会话圈数、轮胎配方与磨损、胎组圈数、圈速、三个赛段时间和有效状态：
   · 最新完成圈显示在最上方；
   · 绿色表示当前最佳有效圈；
   · 红色表示游戏标记的无效圈；
   · Flashback 后以最终重新完成并通过终点线的该圈记录为准。

6. “圈速分析”
   打开离线单圈对比与驾驶指标窗口。具体方法见第八节。

7. “安全停止并关闭”
   停止 UDP 监听，排空待写数据，更新元数据，关闭数据库后退出程序。


六、推荐采集流程
----------------------------------------------------------------------
1. 启动采集程序。
2. 确认程序端口与游戏端口一致。
3. 启动游戏并进入赛道。
4. 确认程序显示了正确的游戏名称，且“最近数据”时间持续更新。
5. 正常驾驶。每次完成一圈后检查圈速和三个赛段时间是否出现。
6. 测试或比赛结束后，点击“安全停止并关闭”。

也可以直接点击窗口右上角“X”。右上角关闭与安全退出按钮使用同一套保存流程，
程序会显示“正在保存/正在等待后台任务”的提示，完成后自动关闭窗口。提示存在时请勿
通过任务管理器强制结束程序，也不要立即关机。


七、采集数据保存在哪里
----------------------------------------------------------------------
每次启动采集或切换 UDP 端口，程序都会创建独立目录：

data\session_YYYYMMDD_HHMMSS\
  raw_packets.bin                         无损保存的原始 UDP 数据，是数据事实源
  telemetry.db                            数据包索引数据库
  metadata.json                           游戏、协议、数量、状态和存储摘要
  foundation\raw_packets.foundation-v2.db 供分析快速复用的基础整理缓存

默认 Raw 使用快速 zlib 分块无损压缩。即使某个包暂时无法解析，其原始字节仍优先保存。

不要随意删除 raw_packets.bin。其他数据库和分析文件都属于可重新生成的派生产物，
Raw 才是最重要的原始档案。需要移动或备份数据时，建议复制整个 session 文件夹。


八、离线圈速分析
----------------------------------------------------------------------
在主界面点击“圈速分析”，会打开单圈对比窗口。

A. 从 Session 生成分析
   适用情况：只有采集到的 Session，还没有分析数据库；或者需要从 Raw 重新生成分析。

   操作方法：
   1. 点击“从 Session 生成分析”。
   2. 选择包含 raw_packets.bin 的 session_YYYYMMDD_HHMMSS 文件夹。
      注意：选择 Session 文件夹，不是选择 raw_packets.bin 文件本身。
   3. 等待后台处理完成。首次处理旧 Raw 时会建立基础缓存，所需时间较长；以后处理同一
      进度的数据会复用缓存，速度会明显提高。
   4. 完成后程序会自动打开分析结果。

   默认分析结果保存在：
   data\session_YYYYMMDD_HHMMSS\analysis_v0.10.0\telemetry_analysis.db

   分析会使用 Flashback 后最终有效时间线，并将完整有效圈按赛道距离标准化，用于比较。
   采集仍在进行时也可以读取已经安全提交的数据快照，但需要最新、最完整结果时，建议在
   Session 结束或进站后再生成。

B. 打开分析数据库
   适用情况：该 Session 已经完成过分析，希望立即查看而不再从 Raw 重建。

   操作方法：
   1. 点击“打开分析数据库”。
   2. 选择 analysis_v0.10.0 文件夹内的 telemetry_analysis.db（旧版本分析数据库也可打开）。

   请勿选择 Session 根目录中的 telemetry.db。telemetry.db 是采集索引，不是圈速分析
   数据库。

C. 分析界面的使用
   · “会话”：选择游戏会话；没有完整有效圈时仍可查看数据状态。
   · “基准圈”：作为比较基准，默认选择最佳圈。新版列表会显示“软胎 第1圈（圈速）”及胎组次序、会话圈号。
   · “对比圈”：选择另一完整圈。
   · 图表显示沿赛道距离的累计时间差、速度、油门和刹车变化。
   · 虚线表示识别出的制动起点。
   · 右侧显示赛段、全油门、制动、滑行、油门刹车重叠、最高速度、换挡和方向修正等指标。

如果数据库中没有完整可比较单圈，程序会拒绝打开。这通常表示该次采集没有完成有效圈，
或生成分析时所需的数据包不完整。


九、“压缩旧 Raw”的用途
----------------------------------------------------------------------
此功能主要用于转换旧版本生成的未压缩 Raw。1.0 新采集的 Raw 默认已经压缩，通常
不需要再次处理。

操作方法：
1. 确保目标 Session 已停止采集。
2. 点击“压缩旧 Raw”。
3. 选择旧的 raw_packets.bin。
4. 选择一个尚不存在的新文件名，例如 raw_packets.compressed.bin。
5. 程序完成压缩后会逐包校验时间、来源和原始字节是否一致。

原文件始终保留，程序不会自动用压缩副本替换旧 Raw。不要在仍在录制的 Session 中手动
替换 raw_packets.bin，也不要把压缩副本直接覆盖到依赖旧物理偏移的旧数据库旁边。


十、常见问题排查
----------------------------------------------------------------------
1. 一直显示“尚未收到游戏 UDP 数据”
   · 检查游戏内 UDP Telemetry 是否开启；
   · 检查游戏和程序端口是否一致；
   · 同机使用时检查目标 IP 是否为 127.0.0.1；
   · 跨电脑时检查目标 IP、防火墙和局域网；
   · 检查是否有其他程序独占了同一个 UDP 端口；
   · 查看 logs\collector.log 中的错误信息。

2. 正在接收，但没有圈速
   · 圈速通常在完整通过终点线后出现；
   · 菜单、维修区、未完成圈或某些特殊阶段不会产生完整圈记录；
   · 确认游戏发送了 Session History 数据包。

3. Flashback 后看到的圈数发生变化
   这是正常行为。程序会识别时间线回退，并以 Flashback 后最终完成的该圈覆盖显示，
   Flashback 前被撤销的分支不会作为最终圈速展示。

4. “打开分析数据库”失败
   请确认选择的是 analysis_v0.10.0\telemetry_analysis.db，而不是 telemetry.db。

5. 从 Session 生成分析耗时较长
   首次处理需要校验 Raw 并建立 foundation-v2 基础缓存。保持程序运行并等待完成；以后对
   同一数据再次分析会复用缓存。如果同时打开了分析任务，关闭程序时也会等待任务完成。

6. 程序无法启动或提示缺少文件
   检查 EXE 同目录的“_internal”是否完整。请重新复制整个发布文件夹，不要只复制 EXE。

7. 程序显示错误，但 Raw 仍在增加
   如果提示“基础数据整理暂停，Raw 采集仍继续”，说明后台解析缓存发生问题，但 Raw 优先
   保存仍在工作。安全结束后保留整个 Session，可利用 Raw 离线恢复。

8. Raw 尾部不完整
   异常断电或强制结束可能截断最后一条记录或压缩块。分析窗口会询问是否仅使用此前完整且
   通过校验的数据。程序不会忽略 CRC 损坏，也不会修改原 Raw。


十一、数据安全和版本更新建议
----------------------------------------------------------------------
1. 正常退出时优先使用“安全停止并关闭”或窗口右上角“X”，等待提示自动结束。
2. 长测、联赛或正式比赛后，建议备份整个 Session 文件夹。
3. 不要在采集中移动、重命名或同步 raw_packets.bin 和数据库文件。
4. 升级程序时保留旧版本目录和 data 文件夹，不要覆盖唯一的原始数据副本。
5. UDP 本身不提供网络重传。跨电脑采集建议使用稳定的有线网络，并避免 Wi-Fi 拥塞。

十三、v0.9.1 轮胎记录说明
----------------------------------------------------------------------
· 主界面增加“轮胎 / 磨损”和“胎组圈数”两栏，例如“软胎 · 磨损 8.0%”。
· 磨损是该圈最后有效采样位置前的四轮平均值，取最近4秒内数据；不是剩余寿命。
  四轮磨损原值及样本来源保存在新版分析数据库中。没有可靠数据时显示“—”。
· 优先使用 Car Damage 四轮磨损；缺少该包时可以使用 Tyre Sets 胎组磨损，数据库会注明来源。
· 按游戏 Session History 的每个轮胎使用段从第1圈开始编号；即使前后都是软胎也独立计数。
  “第N套”表示本会话的第N次轮胎使用段，并非轮胎库存编号。
· 编号包含出站圈、回站圈和无效圈；不等同于只计算飞驰圈，也不等同于旧胎的累计胎龄。
· 同一套旧胎重新装车可产生新的使用段，磨损不会因重新编号而归零。
· 单圈选择示例：软胎 第1圈（1:20.716） · 第2套/总第5圈。会话圈号用于区分同名圈。
· 分析右侧驾驶指标增加轮胎、胎组圈数及平均磨损。
· Flashback 后撤销的圈及其磨损不再作为最终记录展示。
· 旧分析数据库仍可直接打开，但没有新轮胎表时保留原会话圈名，并显示未知轮胎/磨损。
  要补充旧数据的轮胎信息，请使用“从 Session 生成分析”重新生成；结果写入
  analysis_v0.10.0，不会覆盖旧版本 analysis 文件夹。

十四、v0.10.0 赛中查看与驾驶段
----------------------------------------------------------------------
1. 默认开启后台单圈分析。正常接收时不需要点击生成分析；按主窗口“圈速分析”即可
   查看当前 Session 已完成的圈。分析窗口约每 1.5 秒检查一次已提交的新结果。
   刚过线的圈需等 Session History 和帧拼接数据到齐，通常有数秒延迟，不保证即时。

2. “驾驶段”指从离开车库到回到车库的一段驾驶，可选择全部或某次出场。普通驶入
   维修区或比赛中的进站不一定回车库，因此不会强制分段；驾驶段不等同于胎组。
   中途开始采集会标注“中途开始”；末段可能仍标注“进行中 / 记录终点”。

3. 数据状态表包含已完成圈：可分析、游戏判定无效、距离覆盖不足、样本不足、
   等待完整数据。只有满足现有质量门槛的圈进入对比；距离覆盖达到 90% 并不证明
   每个 UDP 包都收到，也不代表中间不存在采样间隙。尚未完成的当前圈不参与对比。

4. Flashback 会撤回受影响圈的旧分析，重新完成并收到最终圈速记录后再生成。
   同一驾驶段筛选也会刷新；已撤回的圈不会保留旧图表。

5. 查看旧 Session：点“从 Session 生成分析”，选择包含 raw_packets.bin 的文件夹。
   首次需要建立基础缓存和分析，耗时与数据量相关；之后只补充新增部分。
   “打开分析数据库”仅浏览已有结果，不重新解析 Raw。旧数据库没有驾驶段元数据时
   显示“全部驾驶段”。导入一个旧数据库不会自动把它迁移或改写。

6. 新结果位于 analysis_v0.10.0 文件夹。数据库及 -wal/-shm 是 SQLite 工作文件，
   采集或分析期间不要手动删除、拆开复制。需复制时先安全关闭程序，再复制整个 Session。
   后台基础缓存及分析会增加磁盘占用，不是额外的 Raw 全量副本。

7. 如需仅采集 Raw，在 config/settings.json 设置 foundation_enabled 为 false；如需
   保留基础整理但关闭自动单圈分析，设置 analysis_enabled 为 false，重启后生效。
   关闭自动分析后仍可从 Session 手动生成或继续分析。

8. 正常退出按顺序停止 UDP、保全 Raw、提交基础数据、提交分析。若后台进度落后，
   保存可恢复检查点，之后从 Session 补齐。异常分析不会让 Raw 采集停止，主窗口
   会提示“单圈分析暂停”。断电、强杀等无法保证最后尚未提交的数据被保存。

十五、1.0 更名与窗口调整
----------------------------------------------------------------------
1. 本程序从 F1 Telemetry Collector 正式更名为 F1 Telemetry Lab，发布显示版本为 1.0。
   原始数据格式、基础缓存和单圈算法不变；旧 Raw 与分析数据库继续兼容。
   为复用 v0.10.0 的增量结果，内部分析目录仍为 analysis_v0.10.0，并非旧版程序。

2. 单圈分析窗口首次打开最大为 1440×940，屏幕较小时自动收敛，并为系统边缘预留空间。
   标题与操作按钮分行；空间较窄时按钮自动换行。底部状态和图表提示不再被图表挤走。
   尚未载入数据时不显示空的单圈状态表；右侧驾驶指标支持上下、左右滚动。

3. 有完成圈后，可点击“展开单圈状态 / 收起单圈状态”查看质量明细。窗口较矮时默认
   收起该表，为曲线保留空间；大窗口中默认展开。手动选择会在本次窗口中保留。
   高缩放或很小的窗口中，曲线的阅读空间仍有限，可以最大化窗口以便仔细比较。

4. 升级时保留旧版文件夹和数据。新程序默认使用自己同目录下的 data/config/logs。
   可先安全关闭旧程序，把旧 config/settings.json 复制到新版 config 文件夹保留端口等
   设置；查看旧数据用“从 Session 生成分析”或“打开分析数据库”，无需搬移或改写 Raw。
   不要同时让两个程序监听同一 UDP 端口，也不要在录制过程中拆开复制数据库工作文件。

十六、1.1 时间区间与操作对照
----------------------------------------------------------------------
1. 在单圈分析中选择基准圈与对比圈，打开右侧“时间区间”页。按距离顺序列出获益、损失
   和小变化。正值表示对比圈比基准圈在该区间更慢；负值表示更快。不是累计时间差。

2. 点击某一区间，左侧曲线会放大到相同距离范围，下方可滚动查看两圈入口、最低及出口
   速度，第一次制动跨越5%的位置、最低速后第一次油门跨越98%的位置、最低前进挡。
   “未观察到跨越”表示区间中没有完整观察到阈值跨越，不等于该圈没有制动或全油门。
   点击“恢复整圈 / 查看汇总”恢复完整曲线和时间差汇总。

3. 官方整圈差来自游戏最终圈速；已观察区间合计来自两圈共同、可靠的距离区间。
   二者差值显示为“未归属差额”，包含起终点未覆盖、采样缺口及计时对齐差异。
   不把差额强行分配到某个弯道。小区间可能合并，但时间变化不会被丢弃。

4. 新生成分析会排除源采样距离间隔超过50米、圈内时间间隔超过1500毫秒、关键字段缺失
   或异常、明显计时回跳的圈。门槛是保守的分析条件，不是“零丢包”证明，也可能排除
   长时间停车的圈。距离覆盖率高不意味着中间没有缺口。
   5米以内相邻位置出现不超过50毫秒的小计时回跳，只在派生分析中做局部单调修正。
   Raw、Header 和原始 telemetry_samples 不变；更大的回跳不采用这种修正。

5. 打开旧分析库仍然只读。程序重新核验所选两圈的源采样，断开不可靠区间；如果只有
   重采样结果而没有足够源采样，则不生成可信的区间曲线。旧逐圈指标不会被自动重写。
   新旧增量检查点保持兼容，默认目录仍是 analysis_v0.10.0，无需全量重新解析 Raw。

6. 区间是按时间差变化划分的分析范围，不是官方弯道编号，也不是几何弯心识别。
   两圈使用同一组距离边界。位置精度受重采样间距限制，通常为5米。
   轮胎配方不同或磨损相差较大时会提示；燃油、天气、辅助、设置和交通等也会影响圈速。
   操作差异是观察结果，不自动等同于时间损失的原因。本版不提供自动调校或驾驶评分。

7. 时间区间列表及详情均可滚动，不需要地图资源或额外分析软件。新版本程序放在
   F1TelemetryLab-1.0.2 文件夹中；不要只复制EXE。

十七、1.2 边界、质量记录与采集保护
----------------------------------------------------------------------
1. 时间对比保留5米网格，并加入两圈共同可靠的实际首尾采样边界，不向源数据范围外
   外推，不用官方圈速补造速度、油门或刹车。未归属差额不保证归零。
   汇总分别列出圈首、内部不可靠区间、圈尾的净时间差。圈首/圈尾项可能混有计时偏差，
   这是算术分解，不等于已经确认异常原因，不自动归因到驾驶操作。

2. 双击“单圈状态”表中的某一圈，查看覆盖边界、典型采样间隔、缺口和未拼齐的帧。
   缺失类型包括运动、圈速及车辆遥测包；Raw偏移用于回查原始记录，是逻辑位置，
   不是压缩文件的物理位置。缺少圈速包时，只能按相邻有效帧范围关联，无法精确归属。
   质量详情附带暂停、模式变化、Flashback等已记录上下文。无IP、玩家姓名和私人路径。

3. 在较稳定的行驶状态下，根据相邻游戏时钟的局部采样节奏识别异常间隔。
   细小异常不直接淘汰整圈，但不跨越该间隔插值、画线或提取驾驶事件；相关指标仅
   描述可观察部分。暂停导致的本地时间停顿、进站状态变化，不直接当作UDP丢包。
   本功能不能测出准确丢包率，也不能恢复游戏未发送或网络已丢失的数据。

4. 图形采集器的写入队列达到60%时，暂缓后台基础整理和单圈分析，降到25%以下后
   恢复。暂停只发生在任务批次之间，不中断正在提交的事务。Raw接收/保存不主动抽样。
   界面仅保留最新完整圈速历史快照，避免界面卡顿时积累大量旧显示状态。

5. 磁盘剩余不足1 GiB时提示并暂缓后台处理；不足128 MiB时停止接收并保存已有队列，
   窗口保持打开，用户释放空间后可重新启动。检查每秒一次，不保证在磁盘骤满、
   磁盘故障、异常超大UDP或外部程序占满空间时仍能完成所有写入。
   接近满载时仍有明确报错保护，不静默丢弃后假装连续录制。后台落后会提示，退出时
   提交可恢复检查点，之后通过“从Session生成分析”补齐。
   metadata.json 的 summary.resource_health 保存采样到的最低磁盘空间、后台积压峰值
   和压力检查次数，便于长测后核对；压力检查次数不是丢包数量或精确暂停时长。

6. 旧数据库直接打开仍只读。继续旧增量分析会添加派生质量表，并从已有玩家样本
   更新质量与驾驶指标，不重新拆解全部Raw。旧库无法凭空补回当时没记录的缺包帧及
   游戏状态变化；需要完整历史质量证据时，请保留旧库，另选输出目录从Raw重建。
   原始Raw和基础缓存格式不变。升级前请安全关闭旧程序，保留旧版文件夹及数据。
