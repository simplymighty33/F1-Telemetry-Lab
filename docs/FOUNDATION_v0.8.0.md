# v0.8.0：采集与分析基础层，第一阶段交付

日期：2026-10-01。目标是为赛中/赛后共用分析准备数据，不开发 overlay、地图重建或高级驾驶建议。

## 已实现与尚未实现

已实现：统一玩家解析、后台增量保存、原始采样/来源保留、进度与数据同事务提交、异常后续建、Flashback 分支标记、自动驾驶段基础记录、按范围只读查询、现有分析接入基础缓存及结果复用。

尚未实现：完整驾驶段反馈界面、手动段标记、逐圈派生指标的持续更新、只为新变化圈重新计算的分析调度。现有分析在基础数据变化后，仍会遍历基础缓存重建派生数据库，但不再重复扫描/解压整个 Raw 或解释每个包体。不能将本版称为完整的实时驾驶诊断系统。

## 数据路径与线程

1. 接收线程保持现有 UDP 接收及少量显示状态处理。
2. 原有有界写入队列保存 Raw、包索引和元数据。Raw 完整记录/块 fsync 后才发布安全读取水位。
3. 新后台任务每次只读一个已提交的压缩块，或最多 512 条未压缩记录；不使用采集队列，分析落后不会对接收施加额外背压。
4. 基础记录与下一次读取位置在同一个 SQLite 事务中提交，使用 WAL/FULL；失败时整批回滚。SQLite 主缓存限制约 4 MiB，上下文与 Struct 缓存有上限。
5. 窗口关闭后先完成 Raw 收尾；后台在有限收尾窗口内处理完整批次，仍有积压则保留可恢复位置。限时不包括操作系统 I/O 本身可能发生的阻塞。

处理任务失败时，主窗口会提示“基础数据整理暂停，Raw 采集仍继续”。Raw 磁盘写入自身失败仍按原有规则终止采集，不能把实际磁盘失败当作正常记录。

新数据目录：

```
session_xxx/
  raw_packets.bin                        # 原有无损档案，不变更格式
  telemetry.db                          # 原有包索引，不变更格式
  metadata.json
  capture.lock                          # OS 锁；崩溃后自动释放，不必删除文件
  foundation/
    raw_packets.foundation.db           # 可重建的基础缓存
    raw_packets.foundation.lock         # 防止两个后台任务同时写入
  analysis_v0.8.0/
    telemetry_analysis.db               # 现有界面可直接读取的派生结果
    analysis_summary.json
    analysis_errors.json
```

SQLite 运行中可能有 `-wal`/`-shm` 文件。不要在录制/处理过程中只复制主数据库；优先安全停止后复制整个 Session。

## 公共数据内容

数值通道完整保留现有 F1 23 对应玩家记录的字段，不强制组成同频大表：

| 包 | 基础表 | 内容 |
|---|---|---|
| 0 | motion | 玩家位置、速度向量、方向向量、G 力、姿态 |
| 2 | lap | 圈/赛段时间、距离、位置、有效性、车手及进站状态、处罚 |
| 5 | setup | 玩家空气动力、差速器、悬挂、几何、制动、胎压和燃油设置 |
| 6 | telemetry | 速度、油门、刹车、转向、挡位、RPM、DRS、温度、压力、路面类型 |
| 7 | status | 辅助设置、制动偏置、燃油、轮胎、引擎功率、ERS、旗号等 |
| 10 | damage | 四轮磨损/损伤、制动与车身损伤、动力单元磨损及故障 |
| 13 | motion_ex | 悬挂运动、轮速/滑移/力、局部速度、角速度/加速度、前轮角等 |

Session、事件、参与者、最终分类、Lobby，以及玩家 Session History/Tyre Sets 存为去重且压缩的上下文快照。非玩家 History/Tyre Sets 和其他车辆的高频数组不展开进基础缓存，但 Header、来源引用和完整 Raw 仍保留；完整全车解码工具仍可使用。游戏隐私设置或未发送字段不会被补造。

每条基础记录关联 Raw 逻辑偏移、接收时间、单调时间和原 Header。Header 的 sessionUID 使用字符串关联，原 64 位值仍在 Header 中；帧号、overallFrameIdentifier、玩家及副玩家索引等完整保留。缺少其他包不妨碍已收到有效通道落库。

基础层不做插值、自动补值或强制采样。旧分析算法为了兼容既有结果，仍使用原有帧组装及低频状态沿用方法；不是已经完成新的精细时间对齐引擎。

## Flashback 与驾驶段

Flashback 将同一 sessionUID 下、回退目标帧之后的既有记录标记为 superseded，Raw 不删除。默认通道查询和驾驶段列表排除这些记录；审计查询可以显式包含它们。有效段由剩余 Lap Data 重建，跨过回车库边界的回退会重新打开有效驾驶段。

按 `driverStatus=0` 识别车库，`1/2/3/4` 表示飞驰圈/回站圈/出站圈/在赛道上；`pitStatus` 单独进入维修区不会结束驾驶段。中途开始采集的驾驶段标记起点不完整。SEND 可结束驾驶段；缺少结束信号时保留 open，不伪造完整结束。当前没有对状态抖动进行复杂推断，也没有手动段标记界面。

驾驶段保存会话、玩家、起止来源偏移、时间与圈号范围。设置、轮胎、燃油和天气的变化仍在各自通道/上下文中保留，后续查询可关联，不仅保存出站瞬间快照。

字段含义参考 [F1 23 协议结构](https://github.com/MacManley/f1-23-udp)，原始规范入口为 [EA F1 23 UDP Specification](https://forums.ea.com/discussions/f1-23-en/f1-23-udp-specification/8390745)。

## 界面与兼容性

- 新录制会话默认后台准备基础数据，入口仍是“圈速分析”→“从 Session 生成分析”。
- 采集中读取已提交基础库的一致性快照，不启动第二个写入任务；反馈明确标记为快照，不代表整个会话结束。
- 旧 Raw 第一次会创建基础缓存，随后复用。旧 `analysis/telemetry_analysis.db` 仍可通过“打开分析数据库”直接读取，默认生成的新结果不覆盖它。
- 同一基础进度、版本与参数的完整分析结果可以直接复用。源追加、参数或算法变化时失效。
- 默认不再自动生成重复 CSV。需要导出时使用分析命令的 `--export`。
- 基础缓存可重建，不是 Raw 的替代品；任何清理都应在停止采集/处理后进行。

## 恢复与校验边界

每个续建游标保存已消费物理前缀的 SHA-256；恢复追加来源时首先验证此前前缀，没有通过验证就拒绝复用。普通未变化缓存的快速打开使用文件大小与纳秒修改时间，并不会每次重新读取整个 Raw。若文件内容与时间戳可能被人为保持一致，应执行显式完整前缀校验。

严格 Raw Replay 读取接口未放宽。对于异常终止留下的截断末尾，界面会先征求用户确认，再只处理通过校验的完整前缀，并把结果标记为 partial_verified_prefix；任何 CRC 错误都不会自动跳过。原 Raw 不修改。仅文件头都不完整时，没有可恢复的有效记录。

开发环境命令：

```
python -m collector.prepare_session SESSION --verify
python -m collector.prepare_session SESSION --recover-tail
python -m collector.analyze_session SESSION
python -m collector.analyze_session SESSION --force-rebuild --export
```

prepare 是对已停止来源的工具，不应对仍在采集的 Raw 直接运行；活动基础库有单写入者保护。

可在 `config/settings.json` 中设置 `"foundation_enabled": false`，关闭采集时的后台整理。Raw 与包索引仍正常保存；之后使用分析功能时仍需首次建立基础缓存。

## 验收结果与真实成本

56 项自动测试通过，涵盖统一解码、两种 Raw、完整 Header、缺包保留、追加续建、同事务回滚、修改前缀拒绝、截断/CRC 区分、Flashback、驾驶段、只读范围查询、写入者互斥、赛中快照、陈旧录制标记、错误隔离、旧数据库保护、修改时间更新与配置开关、GUI 恢复确认和空闲关闭唤醒后的最后一批收尾。

完整 v0.4.0 长测：624,609 包、0 解析错误、4 个游戏会话、11 个最终圈、12 次 Flashback、11,603 个距离采样点。11 张分析表逐行序列化 SHA-256 与原分析数据库完全相同，不比较生成时间、输出路径等 metadata。

| 本机测试阶段 | 用时 | 说明 |
|---|---:|---|
| 旧 Raw 首次准备基础缓存 | 18.68 秒 | 包含全文件 CRC/解析/基础写入 |
| 基础缓存生成现有分析 | 9.88 秒 | 仍遍历基础记录，不再拆解 Raw 包体 |
