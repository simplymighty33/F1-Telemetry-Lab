# v0.7.0 无损压缩验收与资源占用研究

日期：2026-09-30（Asia/Shanghai）。测试环境：Windows 10 19045，Python 3.13.15，PyInstaller 6.22.3，本机 18 个逻辑处理器。容量统一使用十进制 MB（1 MB = 1,000,000 字节）；CPU 表格以一个逻辑核心全忙为 100%。

## 已交付内容

新采集默认写 Raw v2：zlib level 1、独立块、未压缩块上限 256 KiB、默认按 256 条记录刷盘。保留全部原始包和接收信息。Replay、全包解析、玩家单圈分析均自动识别 v1/v2。每块同时校验块头、解压长度、包数、时间边界、块 CRC 和包 CRC。磁盘索引保存物理块位置和块内位置，可只解压目标块读取指定包。

索引提交前先确保 Raw 刷盘；空闲约一秒时写出未满尾块；正常退出排空队列。旧文件转换只生成新的压缩/还原副本，逐包比较后发布，不替换原文件。截断恢复需明确启用 `--recover-tail`，恢复结果标记为 `recovered_prefix`；CRC 损坏直接拒绝。

实时界面增加“压缩旧 Raw”。入口位于“离线圈速分析”窗口。源码工具为 `collector.compress_archive`，EXE 也支持 `compress-raw SOURCE --output NEW_FILE --report NEW_JSON`。旧配置文件缺少压缩设置时自动继承默认值。

## 实际存储预算

| 产物 | 原版 | v0.7 采集路径 |
|---|---:|---:|
| Raw | 670.712 MB | 149.583 MB |
| 采集索引数据库 | 159.830 MB | 169.476 MB |
| Raw + 采集索引 | 830.542 MB | 319.059 MB |

实时采集路径为了保证索引提交时 Raw 已持久化，会在数据库批次边界封块，因此相同长测 Raw 为 149.6 MB，比独立转换工具的 147.3 MB 稍大；两者都保存全部数据，约减少 78%。索引新增块坐标后略增大，目前仍完整保留。

整套 Raw + 索引减少约 61.6%，并非整个 Session 都减少 78%。按这次有效数据时间 2228.125 秒折算，新 Raw 约 0.242 GB/小时，连同完整采集索引约 0.516 GB/小时。若保留当前分析数据库及导出，约 0.63 GB/小时。2 小时活动可先按约 1.3 GB 预算；不同游戏模式、有效车辆和频率会改变实际值。

转换旧数据时原件与压缩副本暂时同时存在，生成副本不会立即释放原件占用。工具的首要保证是完整校验及保留原件，原件的长期归档策略应另行决定。

## CPU 与内存测量

先对同一批 30,000 个真实包执行独立阶段测试，每个阶段在新的 Python 进程内运行，流式读入而非一次装入整场数据。CPU 数据包含源 Raw 顺序读取与校验，因此属于阶段上界估计，不等于实时 EXE 的精确 CPU。

| 阶段 | CPU 时间 | CPU/包 | 按 350 包/秒折算单核 |
|---|---:|---:|---:|
| 只读源 Raw | 0.1875 秒 | 6.250 μs | 0.219% |
| 不压缩 Raw 写入 | 0.4219 秒 | 14.062 μs | 0.492% |
| level 1 压缩 Raw 写入 | 0.7813 秒 | 26.042 μs | 0.911% |
| level 6 压缩 Raw 写入 | 0.9375 秒 | 31.250 μs | 1.094% |
| 不压缩采集 + 索引 | 0.9688 秒 | 32.292 μs | 1.130% |
| level 1 采集 + 索引 | 1.3125 秒 | 43.750 μs | 1.531% |
| 原实时 Session/历史解码 | 0.8906 秒 | 29.688 μs | 1.039% |
| 优化后实时 Session/历史解码 | 0.3281 秒 | 10.938 μs | 0.383% |

完整 624,609 包的采集路径峰值工作集为 26.96 MB，吞吐约 18,476 包/秒。该测试使用快速离线注入，不代表 UDP 网络传输极限。写入路径的内存没有随整场 Raw 容量增长。

随后测量真正的 Windows EXE，使用本机 UDP 回放真实包的一个有界片段，记录目标进程 CPU 时间和工作集，窗口隐藏。此试验验证接收、界面后台更新、落盘和安全关闭，不将循环回放当成新的有效游戏圈。

| EXE 场景 | 单核 CPU | 工作集 | 接收验证 |
|---|---:|---:|---|
| 原重复刷新下待机，4 秒 | 2.33% | 37.8 MB | 用于定位重复 UI 刷新 |
| 优化后待机，两次 4 秒 | 0–0.39% | 37.4–37.8 MB | 正常监听 |
| 优化后 350 包/秒，20 秒 | 5.62% | 峰值 40.87 MB | 7,000 / 7,000，软件丢包 0 |
| 优化后 1400 包/秒，10 秒 | 7.59% | 峰值 42.09 MB | 14,000 / 14,000，软件丢包 0 |

收包 CPU 计时包括发送进程启动等待及约 2 秒尾块结算。两个 EXE 都安全退出（退出码 0），pending_packet_count=0，Session 状态 complete。350 包/秒时按本机 18 个逻辑处理器平均归一化约为整机 0.31%，1400 包/秒约为 0.42%；任务管理器短时读数会受调度、窗体可见性和 CPU 型号影响。

这不是游戏电脑上的两小时新压缩格式实测。仍需下一次实际游戏长测核对压缩版本、Raw/索引包数、帧连续性及完整 Replay。

## 已实施的精简

1. **玩家历史先判断车辆编号。** 原界面会先将每份 AI Session History 的 100 个历史槽完整解码，再判断不是玩家。改为在有效固定长度包中先读取 car_idx，只有玩家包进入界面历史解码。全部 AI 原始包仍归档，完整解析和离线分析仍可访问。完整长测上新旧实现的 16 次显示历史更新逐一相同。
2. **界面只更新变化的文字和颜色。** 保留 200 ms 检查周期；状态、模式、赛道、目录、错误和状态点仅在变化时设置。无数据时不再反复触发控件绘制。最近包时间仍按原频率更新。
3. **移除当前功能未使用的 TLS/OpenSSL 打包依赖。** 当前产品功能是 UDP 与本地文件，不使用 HTTPS。打包排除 ssl/_ssl/_hashlib，SHA-256 使用 CPython 内置实现。压缩及还原后的独立 SHA-256 比对在实际精简 EXE 中已通过。将来新增 HTTPS 功能时，需恢复相关依赖并测试。

| 发布目录 | 文件数 | 总大小 |
|---|---:|---:|
| v0.6.0 原发布目录 | 995 | 29,595,376 字节 |
| v0.7.0 新发布目录 | 991 | 23,622,514 字节 |

发布目录减少 5.973 MB（约 20.2%）；EXE 主文件约 2.20 MB，余下是独立运行所需 Python/Tk/SQLite 等运行库。压缩功能未增加第三方运行依赖。多文件发布形式继续保留；单文件发布会在启动时解包依赖，它不是减少运行依赖的方法。[PyInstaller 官方说明](https://pyinstaller.org/en/stable/operating-mode.html)

## 后续研究优先级

第一优先是**紧凑采集索引**。压缩后索引的 169.5 MB 已超过 Raw 的 149.6 MB；重复 session_id、文本 timestamp、IP 和长 raw_reference 可以改为会话/来源表引用及数字坐标，文本按需生成。必须保留或提供查询兼容层，并继续验证随机读取和 Raw/索引一致性，不能未经迁移直接删列。完成此项前默认继续保留完整索引。

第二是**派生数据生命周期**。完整 JSONL、标准化 CSV 和分析 SQLite 都可由 Raw 重建。未来可增加“长期归档只留压缩 Raw + 摘要”选项，并在重建验证后由用户管理派生文件。当前不自动删除历史分析结果。

第三是**离线分析内存峰值**。`_source_rows` 仍为一圈创建多个字典，曲线和导出也保留必要的单圈点集。后续可用更小的样本对象、按圈流式处理以及按画布像素抽取显示点；原数据库点集保留。采集应继续与完整分析隔离，避免实时分析成为比赛时的持续开销。

压缩级别、队列容量和 flush 频率有明显权衡。默认 level 1 是轻量选择；减小队列会降低突发余量，延长刷盘间隔会增加异常退出时尚未持久化的尾部数据，均不能只为追求一个更小的数值盲目改变。[Python zlib 官方文档](https://docs.python.org/3/library/zlib.html)
