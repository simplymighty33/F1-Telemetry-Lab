# F1 Telemetry Lab 1.0.3c — Session 分档测试版

新采集按 `(packetFormat, sessionUID)` 自动保存到独立目录，UDP 监听不中断。

目录示例：

`session_20261002_153000_F1-23_澳大利亚_练习赛2_UID-000000000000004D`

开始时间在前，可按名称查找比赛进程。UID 使用十六进制完整保存；metadata 中保留十进制 UID、档案身份、游戏模式、赛道、环节、赛季/周末/环节关联标识和上下文变化历史。相同 UID 再次启动录制仍创建新目录；重名加后缀，不覆盖已有数据。

每个目录内仍包含 raw_packets.bin、telemetry.db、metadata.json；后台基础整理和增量分析也分别保存在该目录。Raw v2 的无损压缩、CRC 和逻辑偏移格式没有改变。

## 查找与分析

- 从主界面打开圈速分析，自动连接当前 Session，无需手动导入 Raw。
- 查看历史记录时，选择名称对应的 Session 目录。要迁移新数据，请在停止采集后复制整个目录，包含 metadata 和分析缓存；新缓存使用档案身份与相对路径绑定。
- 新档案的身份保护用于防止误用不同来源的分析缓存，并非对抗篡改的密码学认证。
- 旧目录不批量改名、拆分或迁移；原有 Raw v1/v2 读取能力保留。旧缓存的私人绝对路径限制不在此次兼容范围内。

## 边界和限制

- 首次数据到达前保留“未归属/等待游戏”目录用于退出诊断。仅识别 Header 时显示“赛道待识别/环节待识别”；第一次有效 Session 包到达后补全名称，再启动实时分析。始终未收到有效 Session 包时，保留待识别名称，停止后可离线整理。
- 名称采用首次可靠识别到的赛道/环节；后台分析启动后不再移动目录。若同一 UID 后续改变环节，上下文变化写入 metadata，不假定环节变化必然产生新 UID。
- 进站、换胎、单圈完成、Flashback、短时收不到 UDP 数据均不创建新目录。收到结束事件后仍可保留同 UID 的最后历史包。
- 旧 UID 的迟到包归回原档案，保留同 UID 接收顺序；无法识别协议/包类型或无法解析 Header 的数据进入独立“未归属”档案，不猜测其 Session。
- Race/Race 2/Race 3 仍不能可靠区分正赛与冲刺赛，名称保留待确认。
- 暂停的 Raw/index 句柄关闭，但保留会话写入锁，避免把仍可能追加迟到包的档案当作静态文件。后台分析同时仅维护一组消费者，切换及收尾不占用接收线程。
- 后台切换期间或存在积压时，历史 Session 的派生结果可能尚未追上迟到数据；停止后“从 Session 分析”会增量补齐。
- 解析/显示异常不能中断 Raw；真正的写盘失败或写入队列满仍会明确报错停止。网络未收到的包、断电时未提交的尾部仍无法保证恢复。

此版须继续进行真实游戏多环节长测；合成回环和 Replay 验证不等于实机耐久验收。
