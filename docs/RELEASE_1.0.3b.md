# F1 Telemetry Lab 1.0.3b — 界面细节打磨

本地测试版，基于1.0.3a全部功能。界面版本1.0.3b、Python版本1.0.3b0、Windows数值版本1.0.3.1。不自动发布GitHub；正式版仍为1.0.2。

## 圈速显示统一

- 主界面逐圈记录标题显示中文赛道与比赛环节，首列为“总圈数”。最新圈仍在最上面，胎组圈数独立保留。
- 分析会话、分析标题、基准/对比圈名和练习复盘使用同一显示规则。
- 圈名示例：`澳大利亚 · 练习赛2 · 总第33圈｜软胎（磨损12.0%）｜1:22.000`。胎组第几套/第几圈保留在独立列与详细指标，不用磨损当作身份标识。
- 总圈数是所选游戏环节的Session History圈号，不跨练习、排位与比赛累加；中途开始采集也不改成从1计数。
- 磨损为现有轮胎跟踪器提供的该圈结束前最后有效四轮平均值；缺少Car Damage时可能来自Tyre Sets备用来源，详细指标保留来源信息。缺失或不可用数值显示“磨损未知”，真实0%仍显示0.0%。这是磨损，不是剩余寿命。
- 练习赛1/2/3、Q1/Q2/Q3及协议明确支持的SQ1/SQ2/SQ3、短/单圈排位、计时赛分别命名。未知赛道/类型保留原始文字，不冒充已识别环节。
- **正赛/冲刺识别边界**：现有官方sessionType只列Race、Race 2、Race 3，没有独立Sprint Race编号。不能凭圈数、比赛顺序或Race 2猜测；这些类型显示“待确认”。2023协议没有独立冲刺排位枚举，因此不声称F1 23能自动可靠识别所有冲刺环节。中文别名不改写Raw、原始枚举或数据库；将来有经过实测验证的额外依据时再增强识别。
- 合法包的会话UID、玩家索引或协议发生变化时，先清除上一环节表格与元信息，等待当前环节数据，防止新标题配旧圈速。Flashback仍按游戏最终圈历史替换。

## 赛中分析入口

正常接收时，点击主界面“圈速分析”自动连接当前录制目录，不需要导入Raw、不触发全量Replay。只看完整、有效且通过数据质量门槛的圈。

连接说明区分等待当前录制、等待完整有效圈、自动刷新、自动分析未开启、资源压力暂缓、分析暂停以及采集已停止。约每1.5秒检查已提交结果；后台可能落后，不保证过线后立即显示。

改变UDP端口产生新录制目录时，仍连接当前采集的分析窗口会自动跟随新目录、清除旧曲线。游戏切换环节后，默认等待新的UID；不会把旧会话结果当成新会话。用户主动选择历史会话时保留选择并标明正在查看历史会话。

“打开分析数据库”与“从Session生成分析”是显式选择其他数据，之后不强制跟随当前采集。关闭并从主界面重新打开分析即可回到当前录制。后台分析关闭或出错时，从Session恢复；Raw采集仍按原有策略独立运行，不在界面线程解析数据包。

小屏幕优先显示连接说明，省略完整数据库路径以保留图表空间；表格继续支持横向/纵向滚动，标题可换行。基准/对比圈选择框过窄时，可把鼠标停在选择框上查看完整圈名；刷新或关闭窗口会收起提示，不保留已撤销圈的旧提示。

## 兼容与测试

没有新增第三方依赖、没有改变Raw/基础缓存格式、派生schema仍为5、分析引擎仍为8。分析库直接打开只读，旧库没有轮胎信息显示未知。1.0.3a与所有旧录制保留；本版不代表新一轮真实游戏长测已经完成。长测步骤仍见 `ENDURANCE_1.0.3a.md`。
